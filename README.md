# Лабораторная работа № 2. Веб-приложение с использованием S3

Учебное веб-приложение для управления бакетами и файлами
в S3-совместимом облачном хранилище VK Cloud Object Storage.

Интерфейс представляет собой простую галерею изображений.
Все обращения к S3 выполняются backend-приложением.
Frontend взаимодействует только с backend через REST API.

## Возможности

- Просмотр списка бакетов.
- Создание нового бакета.
- Выбор бакета и просмотр его объектов.
- Загрузка изображения или другого непустого файла размером до 1 МБ.
- Миниатюры PNG, JPEG, GIF, WebP, AVIF и BMP.
- Просмотр изображений в отдельной вкладке и скачивание файлов.
- Безвозвратное удаление файла со всеми версиями и маркерами удаления.
- Очистка и удаление непустого бакета.
- Отдельное подтверждение удаления файлов и бакетов.
- Сообщения об успешных операциях, ошибках и состоянии загрузки.

При загрузке к имени файла добавляется UUID.
Повторная загрузка одноимённого файла создаёт отдельный объект.

## Настройка S3

1. Создайте проект и Object Storage у облачного провайдера.
2. Создайте отдельную учётную запись S3 и пару ключей доступа.
3. Настройте права для операций, используемых приложением.
4. Сохраните настройки в локальном `.env`.

Для VK Cloud в этой работе используются:

- endpoint: `https://hb.ru-msk.vkcloud-storage.ru`;
- region: `ru-msk`;
- класс хранения: Hotbox.

Приложение работает с бакетами как с включённым, так и
с не включавшимся версионированием. Учитывается также
приостановленное версионирование.

Учётной записи нужны права на используемые операции:

- `s3:ListAllMyBuckets`, `s3:CreateBucket`, `s3:DeleteBucket`;
- `s3:ListBucket`, `s3:GetBucketVersioning`, `s3:ListBucketVersions`;
- `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`;
- `s3:DeleteObjectVersion`;
- `s3:ListBucketMultipartUploads`, `s3:AbortMultipartUpload`.

Способ назначения прав зависит от облачного провайдера.
Публичный доступ к файлам для работы приложения не требуется.

## Переменные окружения

Безопасный шаблон `.env.example`:

```dotenv
S3_ENDPOINT=https://hb.ru-msk.vkcloud-storage.ru
S3_REGION=ru-msk
S3_ACCESS_KEY=
S3_SECRET_KEY=
```

Назначение переменных:

| Переменная | Значение |
| --- | --- |
| S3_ENDPOINT | HTTPS-адрес S3 API |
| S3_REGION | Регион для подписи запросов |
| S3_ACCESS_KEY | Идентификатор ключа доступа |
| S3_SECRET_KEY | Секретный ключ доступа |

Из корня репозитория создайте `.env` на основе шаблона.
Следующий блок сохраняет файл в UTF-8 без BOM и сохраняет
уже существующий `.env` без изменений:

```powershell
$localEnvPath = Join-Path -Path (Get-Location) -ChildPath '.env'

if (!(Test-Path -LiteralPath $localEnvPath)) {
    $envTemplateText = Get-Content -LiteralPath '.env.example' -Raw -Encoding UTF8
    [System.IO.File]::WriteAllText(
        $localEnvPath,
        $envTemplateText,
        [System.Text.UTF8Encoding]::new($false)
    )
}

notepad $localEnvPath
```

Заполните ключи только в локальном `.env`.
Не добавляйте реальные ключи в `.env.example`, исходники или README.

Backend импортирует корневой `.env` как файл свойств.
Он должен существовать при запуске приложения.
Значения S3 не передаются во frontend.

## Запуск backend

В отдельном окне PowerShell из корня репозитория:

```powershell
Set-Location backend
mvn spring-boot:run
```

Запускайте backend из папки `backend`, чтобы корректно
разрешался путь `../.env`.

Адрес backend: `http://127.0.0.1:8080`.

Пример проверки:

```powershell
Invoke-RestMethod -Method Get -Uri 'http://127.0.0.1:8080/api/buckets'
```

Команда возвращает список доступных учётной записи бакетов.

## Запуск frontend

В другом окне PowerShell из корня репозитория:

```powershell
Set-Location frontend
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173/`.

Backend и frontend должны работать одновременно.
Запросы `/api` локальный сервер Vite передаёт в backend
по адресу `http://127.0.0.1:8080`.

Для остановки каждого сервера нажмите Ctrl+C в его терминале.

## Сборка

Backend, из папки `backend`:

```powershell
mvn package
```

Frontend, из папки `frontend`:

```powershell
npm run build
```

Результат сборки backend находится в `backend/target`,
frontend — в `frontend/dist`.

Сборка frontend не запускает backend.
Инструкция локального запуска использует `npm run dev`
и настроенный в Vite прокси.

## REST API

Базовый адрес: `http://127.0.0.1:8080`.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/api/buckets` | Список бакетов |
| POST | `/api/buckets` | Создание бакета |
| DELETE | `/api/buckets/{bucket}?confirmed=true` | Очистка и удаление бакета |
| GET | `/api/buckets/{bucket}/objects` | Список объектов |
| POST | `/api/buckets/{bucket}/objects` | Загрузка файла |
| GET | `/api/buckets/{bucket}/objects/content?key=...` | Скачивание файла |
| GET | `/api/buckets/{bucket}/objects/content?key=...&download=false` | Просмотр поддерживаемого изображения |
| DELETE | `/api/buckets/{bucket}/objects?key=...&confirmed=true` | Удаление объекта со всеми версиями |

При создании бакета передаётся JSON:

```json
{
  "name": "my-s3-gallery-unique-name"
}
```

Имя должно быть уникальным у провайдера и соответствовать правилам S3:
3–63 символа, строчные латинские буквы, цифры, точки и дефисы.
Начало и конец — буква или цифра.
Дополнительные ограничения проверяет backend.

При загрузке передаётся `multipart/form-data` с полем `file`.
Текущий максимальный размер файла — 1 МБ.

Ключ объекта в параметре `key` нужно URL-кодировать.
Frontend использует `encodeURIComponent`.

Список объектов содержит поля:

- `key` — ключ объекта;
- `size` — размер в байтах;
- `lastModified` — время изменения в UTC, формат ISO 8601.

При успехе создания бакета или загрузки файла возвращается HTTP 201.
При успешном чтении и удалении — HTTP 200.
Ошибки операций возвращаются с соответствующим HTTP-статусом;
обработанные приложением ошибки содержат JSON-поле `error`.

Без `confirmed=true` запрос удаления отклоняется с HTTP 400.
В интерфейсе подтверждение запрашивается отдельным диалогом.

Скачивание использует `Content-Disposition: attachment`.
Просмотр поддерживаемого изображения использует `inline`.
Остальные типы файлов предлагаются для скачивания.

## Особенности удаления

Удаление файла безвозвратно удаляет все найденные версии
и маркеры удаления только выбранного ключа.
Объекты с похожими именами не затрагиваются.

Перед удалением бакета backend:

1. Получает список незавершённых multipart-загрузок.
2. Получает список объектов либо всех версий и маркеров удаления.
3. Прерывает незавершённые загрузки.
4. Удаляет содержимое.
5. Удаляет сам бакет.

Обходятся все страницы списков S3.

Очистка не является атомарной операцией:
если удаление прервётся ошибкой, часть данных уже может быть удалена.
Состояние бакета следует обновить перед повторной попыткой.
Во время очистки не следует параллельно записывать в этот бакет
через другие приложения.

Приложение не обходит блокировки хранения, установленные провайдером.

## Проверка основных функций

Для проверки используйте отдельный тестовый бакет.

1. Создайте бакет через интерфейс и проверьте появление в списке.
2. Выберите его: должен отображаться пустой список файлов.
3. Загрузите небольшой PNG или JPEG.
4. Проверьте сообщение об успехе и появление миниатюры.
5. Откройте изображение через «Просмотреть».
6. Скачайте его через «Скачать» и откройте полученный файл.
7. Откройте диалог удаления файла и отмените действие:
   файл должен остаться после обновления списка.
8. Подтвердите удаление тестового файла:
   карточка должна исчезнуть.
9. Загрузите в тестовый бакет ещё один файл.
10. Отмените удаление бакета и проверьте, что он остался.
11. Подтвердите удаление непустого тестового бакета:
    приложение должно очистить содержимое и удалить бакет.
12. Проверьте результат в панели облачного провайдера.

Для проверки ошибок можно отправить недопустимое имя бакета
или выбрать файл больше 1 МБ.
Должно появиться понятное сообщение, без успешного выполнения операции.

## Проверка Git перед публикацией

Из корня репозитория:

```powershell
git status --short
git check-ignore -v -- .env frontend/node_modules/ frontend/dist/ backend/target/
git ls-files -- .env '**/.env'
```

Настоящий `.env` не должен отслеживаться.
В репозитории должны находиться исходники, `.env.example`,
настройки сборки и `frontend/package-lock.json`.

Публикация репозитория выполняется отдельно после проверки его содержимого.
